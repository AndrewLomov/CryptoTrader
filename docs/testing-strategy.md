# Стратегия тестирования CryptoTrader 0.1

Пирамида идёт снизу вверх: быстрые проверки инвариантов, затем контракт адаптера без сети, затем PostgreSQL в контейнере, и только после появления точки входа — дымовой прогон API. Нижний слой не открывает сокет и не зависит от Docker. Верхний слой не подменяет собой расчёт стратегии или риска.

## Пирамида

1. **Модульные тесты.** Domain, индикаторы, `TrendFollowingStrategy`, `RiskManager`, `WalkForwardSplitter`, `BacktestEngine`. Время UTC, деньги `decimal`. Сети, базы и ключей нет.
2. **Контрактные тесты биржи.** Один адаптер Bybit. JSON kline с числовыми строками проверяется через публичный клиент и подставленный `HttpMessageHandler`. Заявка в 0.1 не уходит в HTTP.
3. **Интеграционные тесты.** Только PostgreSQL из Testcontainers. Метка `[Trait("Category", "Integration")]`. Каждый тест создаёт свою пустую базу на строке подключения контейнера и применяет миграции EF. Bybit не вызывается.
4. **Дымовой тест API.** Допустим только `WebApplicationFactory<Program>`, когда `Program` — `public partial`. Пока файла `Program.cs` нет, Host остаётся библиотекой, пакет `Microsoft.AspNetCore.Mvc.Testing` в тестовый проект не добавляется, и дымовой тест не входит в набор.

Обычный прогон `dotnet test` без фильтра гоняет модульные и контрактные тесты. Интеграционные тесты требуют Docker. Если Docker недоступен, тест падает исключением контейнера. Подключение к базе разработчика не используется.

## Живая биржа

Тесты этой версии не обращаются к живой или testnet-бирже.

- Заявка не отправляется. `BybitTradingClient.SubmitAsync` проверяется на код `LiveTradingDisabled` и `UnknownState = false`.
- Реальный API-ключ не читается и не подставляется.
- Сокет к `api.bybit.com` не открывается. Разбор kline идёт через `HttpClient` с адресом `http://127.0.0.1` и обработчиком, который отвечает фикстурой.
- Интеграционные тесты не создают биржевой клиент.
- Отдельные прогоны против demo или testnet, если появятся позже, остаются необязательными и не блокируют обычный набор при отсутствии внешней сети.

## Случаи из спецификации

Раздел 21 технического задания и обязательные сценарии 0.1 сопоставлены с тестами. Пробелы перечислены отдельно: для них нет устойчивого производственного входа либо сценарий ещё не автоматизирован.

### Интеграционные тесты

| Случай | Где проверяется |
|---|---|
| Миграция на пустой базе | `DatabaseTests.Migration_applies_on_an_empty_database` |
| Повторная запись свечи с тем же открытием обновляет одну строку | `DatabaseTests.Candle_upsert_keeps_one_row_and_updates_ohlc` |
| Повторный `ClientOrderId` в одном счёте отклоняется | `DatabaseTests.Duplicate_client_order_id_is_rejected` |

Восстановление состояния заявки, paper execution и endpoints API с авторизацией в этом наборе ещё не автоматизированы. Дымовой API-тест не пишется, пока нет публичного `Program`.

### Контракт биржи

| Случай | Где проверяется |
|---|---|
| Нормализация decimal и UTC для kline | `BybitContractTests.Kline_numeric_strings_parse_to_decimal_and_utc` |
| Заявка не уходит наружу и не остаётся в неизвестном состоянии | `BybitContractTests.SubmitAsync_returns_live_trading_disabled_and_known_state` |

Отдельных тестов пока нет для каталога символов, rate limit, недоступности API, reconnect, частичного исполнения на бирже, неизвестного статуса заявки и отсутствия секретов в логах. Реальный testnet в набор не входит.

### Backtesting

Повтор, конфликт стопа и тейка, комиссия со проскальзыванием и отсутствие look-ahead закрыты `BacktestEngineTests`. Разделение in-sample и out-of-sample закрыто `WalkForwardSplitterTests`: оптимизатора параметров в 0.1 нет, проверяется граница окна.
