# Трендовая стратегия и backtest 0.1

Прибыльность стратегии не установлена. Параметры по умолчанию — стартовая гипотеза для проверки торгового цикла, а не оптимальная конфигурация и не рекомендация к счёту. В этом документе только правила, формулы и допущения модели. Результатов прогона здесь нет.

Стратегия `trend-following` версии `0.1.0` («Trend Following Swing») торгует только long spot. Short не генерируется. Параметры читаются из JSON конструктором стратегии. Переменные окружения не используются.

## Параметры

`TrendFollowingParameters.Parse` принимает JSON с именами свойств без учёта регистра. Пропущенные поля получают значения по умолчанию.

| Свойство | По умолчанию | Смысл |
|---|---:|---|
| `EmaFastPeriod` | 50 | Период быстрой EMA на старшем таймфрейме |
| `EmaSlowPeriod` | 200 | Период медленной EMA на старшем таймфрейме |
| `RsiPeriod` | 14 | Период RSI на рабочем таймфрейме |
| `AtrPeriod` | 14 | Период ATR на рабочем таймфрейме |
| `RsiCrossThreshold` | 40 | Порог пересечения RSI снизу вверх |
| `AtrStopMultiplier` | 2 | Множитель ATR для stop |
| `AtrTakeProfitMultiplier` | 4 | Множитель ATR для take profit; `0` отключает take profit |

Период меньше 1 или быстрый период больше либо равен медленному даёт `ArgumentException`.

## Правила сигнала

Вызывающий код передаёт уже закрытые свечи. Стратегия дополнительно отбрасывает свечи с `IsClosed = false` и свечи с `CloseTime` позже `AsOfUtc`. Будущие значения в индикаторы не попадают. Одинаковое время открытия сохраняется один раз: остаётся первая свеча в стабильном порядке по времени открытия.

Сигнал считается на последней видимой рабочей свече. Для входа нужны все условия сразу:

1. На старшем ряде хватает истории для медленной EMA, на рабочем — для RSI и ATR, включая RSI предыдущей рабочей свечи.
2. На последней старшей свече `EMA fast > EMA slow` и `Close > EMA slow`.
3. RSI предыдущей рабочей свечи строго ниже порога, RSI текущей рабочей свечи больше либо равен порогу.
4. Открытой позиции нет (`HasOpenPosition = false`).

Цена сигнала — close рабочей свечи. ATR — ATR этой же свечи.

```text
stop = close - ATR * AtrStopMultiplier
take = close + ATR * AtrTakeProfitMultiplier    если множитель > 0
```

Stop должен быть больше 0 и строго ниже close. Иначе сигнала нет. Take profit добавляется только при множителе больше 0 и цене выше close.

Если старший тренд сломан (`EMA fast <= EMA slow` или `close <= EMA slow`) и позиция открыта, стратегия возвращает `ExitLong`: цена — close рабочей свечи, stop и ATR пустые. Если истории для EMA ещё нет, список сигналов пуст и для входа, и для выхода.

`SignalId` детерминирован. Это GUID из первых 16 байт SHA-256 (UTF-8, конструктор `Guid` от этих байт) строки с разделителем LF:

```text
trend-following
{instrumentId}
{openTimeUtc}
0.1.0
```

`openTimeUtc` — время открытия рабочей свечи в формате `yyyy-MM-ddTHH:mm:ss.fffffffZ`. `Guid.NewGuid` не используется, поэтому один и тот же бар даёт один и тот же идентификатор.

## Индикаторы

Ряд результата той же длины, что и вход. Пока значения нет, элемент `null`. Индекс 0 — первая входная точка. Деление выполняется в `decimal`.

### EMA

`k = 2 / (period + 1)`.

На индексе `period - 1` стоит SMA первых `period` значений:

```text
EMA[period - 1] = (v[0] + ... + v[period - 1]) / period
EMA[i] = v[i] * k + EMA[i - 1] * (1 - k)    для i >= period
```

Индексы `0 .. period - 2` равны `null`. Для периода 200 первое значение появляется на индексе 199, то есть нужно 200 закрытий.

Пример формулы, не результат торговли: ряд `1, 2, 3, 4, 5`, период 3. SMA на индексе 2 равна 2, `k = 0.5`, далее `3`, затем `4`.

### RSI (Wilder)

Изменение свечи `i` (для `i >= 1`) равно `close[i] - close[i - 1]`. Прирост — положительная часть, потеря — модуль отрицательной части.

Первые средние — простые средние первых `period` изменений. Они относятся к индексу `period`:

```text
avgGain = (gain[1] + ... + gain[period]) / period
avgLoss = (loss[1] + ... + loss[period]) / period
```

Дальше, для `i > period`:

```text
avgGain = (avgGain * (period - 1) + gain[i]) / period
avgLoss = (avgLoss * (period - 1) + loss[i]) / period
```

```text
RSI = 100 - 100 / (1 + avgGain / avgLoss)
```

Если `avgLoss = 0` и `avgGain = 0`, RSI равен 50. Если `avgLoss = 0` и `avgGain > 0`, RSI равен 100. Если прироста нет, а потеря есть, формула даёт 0. До индекса `period` значения `null`. Для периода 14 первое значение стоит на индексе 14 и требует 15 закрытий.

### ATR (Wilder)

Истинный диапазон использует предыдущее закрытие, поэтому у свечи 0 истинного диапазона нет:

```text
TR[i] = max(high[i] - low[i], |high[i] - close[i - 1]|, |low[i] - close[i - 1]|)    для i >= 1
```

Первый ATR — SMA первых `period` истинных диапазонов (`TR[1] .. TR[period]`) и записывается на индекс `period`. Дальше сглаживание Уайлдера:

```text
ATR[i] = (ATR[i - 1] * (period - 1) + TR[i]) / period    для i > period
```

Для периода 14 первое значение стоит на индексе 14. Расчёт ведётся в `decimal`, не в `double`.

## Исполнение backtest

Движок `BacktestEngine` версии `0.1.0` не ходит на биржу и в базу и не читает `DateTime.UtcNow`. Отчёт — функция свечей и параметров.

Рабочие свечи: закрытые, `OpenTime >= FromUtc` и `CloseTime <= ToUtc`, по возрастанию `OpenTime`. Из двух свечей с одним открытием сохраняется первая. На баре T стратегия видит рабочие свечи до T включительно и старшие свечи с `CloseTime <= T.CloseTime`. Старшие свечи до `FromUtc` остаются доступны, если они уже закрыты: они нужны для прогрева EMA. Рабочие свечи вне окна в индикаторы не входят.

Книга одна: `PortfolioLedger` со стартовым капиталом, котируемым активом инструмента, биржей запроса и счётом `00000000-0000-4000-8000-0000000000b1`. Покупка и продажа проходят через `ApplySpotFill`. Отдельного кассового учёта нет.

Вход long, который одобрил `IRiskManager`, исполняется на открытии следующей рабочей свечи:

```text
fill = open * (1 + slippageBps / 10000)
```

Цена не округляется к шагу тика: округление покупки вниз улучшило бы цену. Количество — одобренное риск-менеджером, повторно не пересчитывается. Комиссия taker: `notional * feeRate`, актив — котируемый.

Stop и take пересчитываются от фактического входа и ATR сигнала. Множители читаются из JSON параметров (`AtrStopMultiplier`, `AtrTakeProfitMultiplier`; если поля нет — 2 и 4):

```text
stop = fill - ATR * AtrStopMultiplier
take = fill + ATR * AtrTakeProfitMultiplier    если множитель > 0
```

Если `stop <= 0`, сделка не открывается.

Пока позиция открыта, каждый следующий бар проверяется целиком, без знания пути внутри бара:

- если `Low <= stop` и `High >= take`, выход по stop;
- иначе если `Low <= stop`, выход по stop;
- иначе если `High >= take`, выход по take.

Цена продажи по stop или take:

```text
exit = trigger * (1 - slippageBps / 10000)
```

Если `ExitOnTrendBreak` включён и стратегия на закрытии вернула `ExitLong`, продажа выполняется на открытии следующего бара с тем же неблагоприятным проскальзыванием, причина `TrendBreak`. Этот выход на открытии происходит раньше проверки stop и take того же бара.

Если на последнем баре позиция ещё открыта, она продаётся по `close * (1 - slippageBps / 10000)`, причина `EndOfData`.

После каждого рабочего бара книга отмечает close (`ObserveMark`) и в кривую добавляется точка equity.

Чистый PnL круга — изменение cash книги от момента до покупки до момента после продажи. Комиссия входа в это изменение входит. Поле `RealizedPnl` позиции для отчёта не используется: в нём нет комиссии входа. Проскальзывание сделки — сумма `|fill - raw| * quantity` по входу и выходу, где `raw` — открытие, stop, take, открытие бара выхода по тренду или close последней свечи. Это оценка разницы цен, а не второе списание поверх cash.

`RunId` — GUID из первых 16 байт SHA-256 (UTF-8, LF) от полей запроса в таком порядке: идентификатор стратегии, версия, JSON параметров как передан, идентификатор инструмента, `FromUtc`, `ToUtc`, начальный капитал, ставка комиссии, slippage в б.п. Время — `yyyy-MM-ddTHH:mm:ss.fffffffZ`. Десятичные числа — инвариантная культура без хвостовых нулей. Одинаковые эти поля дают одинаковый `RunId`. Одинаковые свечи и параметры дают одинаковые числа отчёта.

## Метрики

Доходность бара простая, не логарифмическая. Перед первой точкой кривой стоит начальный капитал:

```text
r[t] = (equity[t] - equity[t - 1]) / equity[t - 1]
```

Стандартное отклонение — выборочное, делитель `n - 1`. Безрисковая ставка нулевая.

```text
Sharpe = (mean(r) / stdev(r)) * sqrt(365.25 * 24 / hours)
Sortino = (mean(r) / downside) * sqrt(365.25 * 24 / hours)
downside = sqrt(sum(min(r, 0)^2) / (n - 1))
```

`hours` — длительность рабочего бара в часах. Для 1h множитель равен `sqrt(365.25 * 24)`.

Sharpe и Sortino равны `null`, если доходностей меньше двух или делитель равен 0. Sortino также `null`, если ни одна доходность не отрицательна. Profit factor равен `null`, если нет сделки с отрицательным чистым PnL; иначе это сумма положительных чистых PnL, делённая на модуль суммы отрицательных. Win rate — доля сделок с чистым PnL больше 0. Expectancy — средний чистый PnL. Max drawdown — наибольшая просадка `(peak - equity) / peak` от пика, который начинается с начального капитала. ROI — `(final - initial) / initial`.

## Walk-forward

Оптимизатора параметров нет. Деление окна делает вызывающий код, не движок:

```text
boundary = WalkForwardSplitter.Split(from, to, inSampleFraction)
```

Оба края — UTC, `0 < inSampleFraction < 1`, `to > from`. In-sample — полуинтервал `[from, boundary)`. Out-of-sample начинается с `boundary` и в подбор параметров не входит. Движок на каждом прогоне получает свой `FromUtc`/`ToUtc` и свои свечи. Итог не оценивается на том же интервале, на котором подбирались параметры: подбора в версии 0.1 нет.

## Допущения и ограничения

- Вход — следующее открытие, проскальзывание неблагоприятное для стороны сделки.
- В одном баре stop и take profit закрываются по stop.
- Funding не моделируется.
- Частичные исполнения и очередь заявок не моделируются.
- Хвост серии закрывается по close последней свечи (`EndOfData`).
- Путь цены внутри бара неизвестен. Если бар открывается хуже stop, модель всё равно продаёт по stop с проскальзыванием, а не по более плохому открытию.
- Шаг цены на fill не накладывается.
- Размер считает риск-менеджер от цены сигнала. Фактический вход — следующее открытие, поэтому cash может не хватить, если открытие сильно хуже сигнала: книга тогда отклоняет fill.
- Один инструмент, только spot long. Короткая позиция, усреднение и пирамида этой стратегией не открываются.

Прибыльность не установлена. Совпадение правил с этим текстом не означает положительное ожидание на любом инструменте или интервале.
