# Интеграция с Bybit и бумажное исполнение

CryptoTrader 0.1 ходит в Bybit только за публичными рыночными данными V5. Приватная торговля не реализована: адаптер не читает API-ключ, не подписывает запрос и не открывает приватный WebSocket.

Собственный тип `BybitOptions` в проекте адаптера связывается с секцией `Bybit`. Он повторяет адреса и лимиты из настроек приложения и не ссылается на проект Application. Именованный `HttpClient` — `bybit`. Базовый адрес — `RestBaseUrl`, таймаут — `TimeoutSeconds`.

## Публичные REST-методы

Все вызовы идут через `GET` и общий ограничитель частоты. По умолчанию не чаще 10 запросов в секунду: перед стартом запроса выдерживается интервал `ceil(1000 / MaxRequestsPerSecond)` миллисекунд. Запросы не обгоняют этот интервал.

| Назначение | Путь |
|---|---|
| Инструмент | `/v5/market/instruments-info?category=spot\|linear&symbol=` |
| Свечи | `/v5/market/kline?category=&symbol=&interval=&start=&end=&limit=1000` |
| Тикер | `/v5/market/tickers?category=&symbol=` |
| Стакан | `/v5/market/orderbook?category=&symbol=&limit=50` |
| История финансирования | `/v5/market/funding/history?category=linear&symbol=&limit=1` |

Идентификатор инструмента: `BYBIT-SPOT-BTCUSDT` или `BYBIT-LINEAR-BTCUSDT`. База и котировка берутся из `baseCoin` и `quoteCoin`. Шаг цены — `priceFilter.tickSize`. Шаг количества — `lotSizeFilter.qtyStep`; у spot, если `qtyStep` нет, используется `basePrecision`. Минимальное количество — `minOrderQty`. Минимальный нотиционал — первое положительное из `minNotionalValue`, `minNotional`, `minOrderAmt`. У linear множитель контракта равен `contractMultiplier`, а если поля нет — `1`. У spot множителя нет.

`List` обходит символы из `Bybit:Symbols` и для каждого запрашивает spot и linear. `FindByExchangeSymbol` сначала ищет spot, затем linear.

Ставка финансирования для spot — `null`. Ноль не подставляется. Для linear сначала читается последняя запись `/v5/market/funding/history`. Если списка нет, ставка берётся из `/v5/market/tickers` (`fundingRate` и `nextFundingTime`). Нет ни ставки, ни времени биржи — снова `null`.

## Свечи и интервалы

| Код домена | Интервал Bybit |
|---|---|
| `1m` | `1` |
| `5m` | `5` |
| `15m` | `15` |
| `1h` | `60` |
| `4h` | `240` |
| `1d` | `D` |

Bybit отдаёт строки от новых к старым: `start`, open, high, low, close, volume. Время — Unix в миллисекундах, UTC. Время закрытия свечи — открытие плюс длительность таймфрейма. Свеча попадает в ответ только если открытие не раньше запрошенного начала и закрытие не позже запрошенного конца. Все такие свечи помечаются закрытыми. Повтор одного открытия сохраняется один раз. Итог сортируется от старых к новым.

Страницы идут по времени начала. Окно страницы — не больше 999 интервалов, чтобы лимит 1000 при порядке «сначала новые» не выкидывал начало окна. Пустой список заканчивает чтение. Больше 20 страниц клиент не запрашивает и пишет предупреждение, если диапазон ещё не закрыт.

`retCode`, отличный от 0, даёт `InvalidOperationException` с текстом `retMsg`. Код `10006` и HTTP 429 — та же ошибка, не пустой список свечей.

## Числа

Цены, количества, ставки, шаги и объёмы читаются как `decimal`. Для JSON-строки используется разбор с инвариантной культурой. Для JSON-числа используется `TryGetDecimal` по исходному тексту. `double` в этих полях не применяется.

## WebSocket

Публичный адрес берётся из `SpotWebSocketUrl` или `LinearWebSocketUrl`. Подписка:

- `kline.{interval}.{symbol}`
- `tickers.{symbol}`
- `publicTrade.{symbol}`
- `orderbook.50.{symbol}`

Каждые 20 секунд клиент отправляет `{"op":"ping"}`. Подтверждённая свеча (`confirm: true`) становится `CandleObserved`. Неподтверждённые обновления не отдаются.

После обрыва клиент ждёт и подписывается заново. Пауза начинается с 1 секунды, удваивается и ограничена 30 секундами, плюс случайные 0–249 миллисекунд. Успешное соединение сбрасывает паузу к 1 секунде. `CancellationToken` прерывает ожидание, чтение и следующее подключение. Адрес сокета в лог не пишется.

## Стакан

Идентификатор обновления — поле `u`. Снимок фиксирует последовательность. Дельта применяется только если её `u` равно предыдущему плюс один. Повтор и более старый `u` игнорируются. Разрыв очищает уровни и отдаёт `OrderBookUpdated` с `IsConsistent = false` и пустыми сторонами: недостающие уровни не достраиваются. Затем клиент один раз перечитывает снимок через REST `/v5/market/orderbook?limit=50`. Неразобранный REST-стакан тоже возвращается неконсистентным, а не пригодным к сделке. Ошибка `retCode` или HTTP 429 при этом остаётся исключением. Три перезагрузки подряд без непрерывного потока разрывают сокет и включают обычный backoff.

## Приватная торговля не реализована

`SubmitAsync` не открывает HTTP и не открывает сокет. Результат: `Accepted = false`, `UnknownState = false`, `ErrorCode = LiveTradingDisabled`. `GetOrderAsync` возвращает `null`. Списки открытых заявок и позиций пустые. `CancelAsync` и `GetAccountAsync` бросают `NotSupportedException`.

Возможности адаптера: spot, linear market data, стакан, финансирование и WebSocket включены. `SupportsLiveOrders` и `SupportsPrivateAccount` выключены. Код биржи — `BYBIT`.

## Бумажное исполнение

`PaperExecutionVenue` работает в режиме `Paper`. Bybit и `PortfolioLedger` не вызываются: книгу проводит приложение, один раз.

Linear perpetual отклоняется с `FuturesLiveForbidden`, заявка не создаётся. Устаревший рынок — `StaleMarketData`. Нездоровый рынок — `ExchangeUnhealthy`.

Для остальных заявок сырая цена берётся так: `Last`, иначе `Ask` для покупки и `Bid` для продажи, иначе `signal.ReferencePrice`. Проскальзывание читается из `IOptions<RiskOptions>`:

- покупка: `raw * (1 + SlippageBps / 10000)`
- продажа: `raw * (1 - SlippageBps / 10000)`

Вход long — покупка, выход long — продажа. Заявка создаётся в `TradingMode.Paper`, затем `MarkSubmitted`, `MarkAccepted` с биржевым номером `paper-{clientOrderId}` и `ApplyFill` на всё количество. Комиссия — `price * quantity * FeeRate`, актив комиссии — котируемая валюта инструмента. Номер сделки — `paper-fill-{clientOrderId}`.

`ReconcileAsync` сразу завершается и не выполняет ввод-вывод.

## Ограничения версии 0.1

Приватные заявки, отмена, баланс и приватный поток не реализованы. Бумажные фьючерсы этой площадкой не исполняются. История свечей обрезается 20 страницами. Подпись запроса и SDK биржи отсутствуют.
